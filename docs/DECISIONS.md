| 2026-11-20 | StyleCop.Analyzers 1.3.180 als feste Version (eigener Code und IDE-Analyzer) | Neueste stabile Version, im NuGet-Cache vorhanden; 1.2.0-beta.556 ist eine Beta. |

Die CLI hält csproj-Änderungen konsistent mit dem SDK. |
| 2026-11-20 | `Microsoft.Build.Framework` und `Microsoft.NET.StringTools` mit `ExcludeAssets="runtime"` (Property `UsesMSBuildLocator`) | Pflicht für MSBuildLocator: MSBuild-Assemblies müssen aus dem installierten SDK geladen werden. |
| 2026-11-20 | StyleCop-Regeln SA0001, SA1600–SA1602, SA1633, SA1101, SA1309, SA1413, SA1000/1009/1010 aus | Keine Pflicht-XML-Doku pro Element und kein Datei-Header; `_feld` statt `this.feld`; C#-12-Collection-Expressions kollidieren mit SA1000/1009/1010 in StyleCop 1.3.180. |
| 2026-11-20 | Layout-Persistenz über eigenes `LayoutState` (Core) statt Dock-Serializer; Layout wird stets aus dem Zustand gebaut | Dock-Serializer müsste alle Panel-ViewModels serialisieren; eigener Zustand ist versionierbar, testbar und robust gegen neue/entfallene Panels. Frei gesplittete Docks werden beim Neustart in den nächstgelegenen Bereich (links/rechts/unten) zurückgelegt. |
| 2026-11-20 | Lokalisierung: `strings.tsv` als Quelle, `tools/strings.py` erzeugt `Strings.resx`/`Strings.de.resx`; XAML über `{l:Loc Key}` | Eine Zeile pro Text hält beide Sprachen synchron; resx bleibt das Laufzeitformat. |
| 2026-11-20 | macOS: Kürzel von Menübefehlen nur über das native Menü, nicht zusätzlich als Fenster-KeyBinding | Sonst würden Befehle doppelt ausgelöst. |
| 2026-11-20 | TextMate-Grammatiken aus TextMateSharp.Grammars, Farben aus eigenen Themes | Grammatiken sind MIT-lizenzierte Sprachdefinitionen; die mitgelieferten VS-Code-/„VisualStudio“-Farbthemes werden bewusst nicht benutzt (eigene Designsprache). |
| 2026-11-20 | Mehrfach-Cursor als eigener Controller über AvaloniaEdit (Extra-Cursor als TextAnchors) | AvaloniaEdit kennt nur Rechteckauswahl. Pfeiltasten beenden den Mehrfachmodus (bewusste Vereinfachung für v1). |
| 2026-11-20 | Bearbeiten-Befehle (⌘C/⌘V/⌘Z …) werden an das fokussierte Steuerelement weitergeleitet | Die native macOS-Menüleiste fängt diese Kürzel ab, bevor TextBox/Editor sie sehen. |
| 2026-11-20 | Avalonia-Build-Telemetrie (`AvaloniaStats` aus Avalonia.BuildServices) per leerem Target in `Directory.Build.targets` abgeschaltet | Projektregel „keine Telemetrie“; der Collector-Prozess blockierte außerdem einen Build. |
| 2026-11-20 | Pfade vor `dotnet`-Aufrufen und vor dem Laden mit `RealPath.Resolve` auflösen | NuGet-Restore scheitert („file already exists“), wenn eine Solution über einen Link-Pfad (macOS `/var` → `/private/var`) geöffnet wird. |
| 2026-11-20 | Eigener `ViewLocator` (nicht recycelnd) statt XAML-DataTemplates für Dock-Inhalte | Avalonias `DataTemplate.Build(data, existing)` gibt das übergebene Steuerelement zurück; Dock reicht beim Tab-Wechsel das alte weiter, dadurch zeigte ein neuer Tab die vorherige Ansicht. |
| 2026-11-20 | Ein einziges `NativeMenu`-Objekt pro Fenster, nur Einträge werden ersetzt | Avalonia.Native wirft „The menu being updated does not match“, wenn ein Fenster ein neues NativeMenu bekommt. |
| 2026-11-20 | Diagnosen: Compiler über `SemanticModel.GetDiagnostics`, Analyzer (später StyleCop) über `CompilationWithAnalyzers` pro Dokument | Pro Datei schnell genug für < 1 s; Solution-weite Analyse läuft nach dem Laden im Hintergrund. |
| 2026-11-20 | Build-Ausgaben zentral in `artifacts.nosync/` (`UseArtifactsOutput`) | Das Repo liegt in iCloud Drive; iCloud legte Konfliktkopien in bin/obj an (`Car 2.cs`, `VsLike 2.dll`), die Tests verfälschten. Ordner mit `.nosync` werden nicht synchronisiert. |
| 2026-11-20 | Code-Fix-/Refactoring-Provider per Reflection aus `Microsoft.CodeAnalysis(.CSharp).Features` statt MEF-Container | Alle 169 + 81 exportierten Provider lassen sich parameterlos erzeugen; ein eigener MEF-Host wäre interne API. Provider, die fehlschlagen oder > 3 s brauchen, werden übersprungen. |
| 2026-11-20 | Parameterhilfe selbst über `SemanticModel.GetMemberGroup` implementiert | Roslyns `SignatureHelpService` ist intern; das öffentliche Semantikmodell reicht für Methoden, Konstruktoren und Konstruktor-Initialisierer. |
| 2026-11-20 | Completion-Commit wird auf den inzwischen weitergetippten Text abgebildet (`CompletionEditMapper`) | Roslyn berechnet die Änderung für den Text beim Öffnen der Liste; AvaloniaEdit filtert danach clientseitig weiter. |
| 2026-11-20 | Projekt-/Solution-Operationen über die `dotnet`-CLI (`new`, `sln add/remove`, `add reference`, `add package`) statt eigener csproj-Manipulation; nur Eigenschaften werden direkt im XML geändert | Die CLI kennt alle SDK-Sonderfälle (slnx, zentrale Paketversionen, Frameworks); Eigenschaften brauchen Formatierungserhalt, den `ProjectFile` mit `LoadOptions.PreserveWhitespace` liefert. |
| 2026-11-20 | Vorlagen aus `dotnet new list` statt fester Liste | Zeigt genau die beim Nutzer installierten Vorlagen, auch eigene. |
| 2026-11-20 | Ziehen im Solution Explorer über eigene Pointer-Gesten statt `DragDrop.DoDragDrop` | `DataObject`/`DoDragDrop` sind in Avalonia 11.3 als veraltet markiert (Warnung = Fehler); innerhalb eines Baums reicht Pointer-Capture. |
| 2026-11-20 | FileSystemWatcher-Ereignisse werden verworfen, wenn der Watcher inzwischen ersetzt/entsorgt ist | Bereits gepostete Ereignisse liefen sonst gegen einen geschlossenen Ordner (Absturz bei gelöschter Solution-Datei; in Headless-Tests übersprang die Ausnahme in den nächsten Test). |
| 2026-11-20 | Starten über `dotnet build` des Startprojekts und anschließend `dotnet run --no-build [--launch-profile …]` | Fehlerliste bekommt die Build-Diagnosen; `dotnet run` wendet Startprofile (Argumente, Umgebungsvariablen) selbst an. |
| 2026-11-20 | Tests über VSTest (`dotnet test --list-tests`, TRX-Logger, `--filter FullyQualifiedName=…/~…`) | Funktioniert für xUnit, NUnit und MSTest ohne eigene Adapter; TRX ist stabil und sprachunabhängig, die Testliste wird über die Einrückung statt über die lokalisierte Überschrift erkannt. |
| 2026-11-20 | `.vslike/settings.json` wird nur bei einer Nutzeränderung geschrieben | Bloßes Öffnen oder Bauen soll keine Dateien ins Repository des Nutzers legen. |
| 2026-11-20 | Das Hauptfenster schließt sich mit seinem `Workbench`; `CodeIntelligence` ignoriert Diagnosen nach `Dispose` | Ursache zufälliger UI-Testfehler, belegt per Reflection-Dump: Arbeit eines beendeten Tests schrieb in dessen offenes Fenster, dadurch entstand Avalonias `MediaContext` im Wurzel-Scope des `AvaloniaLocator`; dessen Render-Job verwarf der Dispatcher-Reset, und alle folgenden Tests bekamen keinen Layout-Pass mehr. |
| 2026-11-20 | StyleCop-Analyzer laufen über `CompilationWithAnalyzers` neben dem Compiler; Analyzer aus Projekt-PackageReferences werden in der IDE nicht zusätzlich ausgeführt | Vermeidet doppelte Meldungen bei Projekten, die StyleCop schon referenzieren; die IDE nutzt immer die eine geprüfte Version. |
| 2026-11-20 | `stylecop.json` wird als AdditionalDocument nur in den unveränderlichen Solution-Snapshot gelegt | Vorgabe „csproj wird nicht verändert“; StyleCop liest seine Einstellungen nur aus AdditionalFiles. |
| 2026-11-20 | „Alle im Dokument beheben“ erst ab zwei gleichen Diagnosen im Dokument; „Alle im Projekt“ immer, wenn der Provider es unterstützt | Ein Fix-All für ein einzelnes Vorkommen wäre nur eine Dublette des Einzel-Fixes. |
| 2026-11-20 | Diagramm-Writer ersetzt nur den Textbereich des per Roslyn gefundenen Knotens (statt Syntaxbaum neu formatieren) | Formatierung, Kommentare und Rest der Datei bleiben garantiert unverändert; Ergebnis ist deterministisch und per Snapshot prüfbar. |
| 2026-11-20 | Diagramm-Schlüssel ist der volle Typname (`Ns.Outer.Typ`\`Arity`); `.cdiagram.json` speichert nur Platzierungen und Ansicht | Code ist die einzige Quelle für Typen/Mitglieder; Umbenennen führt den Schlüssel im Layout mit. |
| 2026-11-20 | Komposition = readonly-Feld bzw. get-only/init-Property eines Solution-Typs, sonst Assoziation | Aus dem Code ableitbar ohne Annotationen; dokumentierte Heuristik. |
| 2026-11-20 | Mitglieder werden in UML-Notation eingegeben, wie sie in der Box stehen | Eine Notation für Anzeige und Eingabe; Parser (`MemberSpec`) ist getestet. |
| 2026-11-20 | Entf-Taste entfernt einen Typ nur aus dem Diagramm; Löschen aus dem Code ist ein eigener Befehl mit Bestätigung | Verhindert versehentliches Löschen von Code. |
| 2026-11-20 | netcoredbg wird bei Bedarf von GitHub geladen (gepinnte Version, SHA-256 aus den Release-Daten im Code) und im Benutzer-Cache abgelegt; im App-Paket (Phase 10) liegt er bereits bei | Lizenz MIT erlaubt Weitergabe; Prüfsumme verhindert manipulierte Downloads; kein vsdbg. |
| 2026-11-20 | Breakpoint-Pfade werden vor dem Senden mit `RealPath` aufgelöst | netcoredbg vergleicht mit dem Pfad aus der PDB; unter macOS ist `/var` ein Symlink auf `/private/var`, sonst bindet der Breakpoint nie (im Test nachgewiesen). |
| 2026-11-20 | Event-Handler einer Debug-Sitzung werden vor `configurationDone` angehängt (`attach`-Callback) | Sonst kann ein früher Halt (Breakpoint in den ersten Zeilen) verloren gehen. |
| 2026-11-20 | Cask ohne `depends_on` für das .NET SDK, stattdessen Hinweis in `caveats` und SDK-Prüfung beim Start | Das SDK wird meist per Microsoft-Installer oder `dotnet-install` eingerichtet; ein erzwungenes `depends_on cask: "dotnet-sdk"` würde es doppelt installieren. |

## Neubau als native macOS-App (2026-11-21)

| Thema | Entscheidung | Grund |
|---|---|---|
| Oberfläche | Swift 6.2, SwiftUI für Fenster, Seitenleiste, Panels, Dialoge; AppKit (NSTextView, TextKit 1) für den Editor | Native Optik und flüssiges Scrollen; TextKit 1 ist bei langen Dateien vorhersehbar schnell und erlaubt temporäre Attribute für Farben und Fehler ohne Undo-Einträge. |
| C#-Analyse | Bleibt in .NET: Prozess `VsLikeEngine` (Roslyn, StyleCop, Diagramm-Writer), JSON-RPC mit Content-Length-Framing über stdin/stdout | Roslyn und StyleCop.Analyzers gibt es nur für .NET; jede Alternative (eigener Parser, fremder Sprachserver) wäre schlechter oder ebenfalls .NET. Der Prozess läuft auf dem installierten SDK (framework-dependent), das App-Paket bleibt bei rund 50 MB. |
| Was in Swift ist | Build, Run, Tests (TRX), NuGet-API, Vorlagen, Solution-/Projektdateien, Debugger-Client (DAP), Lexer, Diagramm-Layout, SVG | Alles, was kein Roslyn braucht, ohne Prozessgrenze und testbar in `VsLikeKit`. |
| Plattform | nur macOS 26, nur arm64 | Auftrag „macOS build only“, Vorbild Seasons; erlaubt die aktuellen SwiftUI-APIs (Glass-Effekt der Diagramm-Werkzeugleiste). |
| Offsets | UTF-16 überall | Roslyn (`string`) und NSString zählen beide UTF-16; keine Umrechnung nötig. |
| Text-Sync | Volltext-Benachrichtigung `document/update` 120 ms nach der letzten Änderung, sofort vor jeder Anfrage | Einfach und robust; Benachrichtigungen verarbeitet die Engine in Reihenfolge, Anfragen parallel. |
| Highlighting | Lexer sofort, Roslyn-Klassifizierung des sichtbaren Bereichs entprellt; Roslyn-Spans werden bei Änderungen verschoben statt verworfen | Kein Flackern beim Tippen. |
| Terminal | SwiftTerm 1.11.2 (MIT), fest gepinnt | Ab 1.12 enthält SwiftTerm Metal-Shader, die nur mit der separat zu ladenden Metal-Toolchain bauen. |
| Run | `dotnet run` im Terminal-Tab | Programme bekommen Standardeingabe; offene Lücke der Avalonia-Version geschlossen. |
| Debugger | netcoredbg 3.2.0-1092 im App-Paket (`Contents/Resources/netcoredbg`), SHA-256 geprüft in `build.sh` | vsdbg ist lizenzrechtlich ausgeschlossen. |
| Quick-Actions | ⇧⌘. öffnet ein Menü an der Schreibmarke (Korrekturen, „Alle beheben“, Refactorings); ⌘. bleibt „Stoppen“ wie in Xcode | Wunsch des Nutzers; Mac-Konvention für ⌘. bleibt erhalten. |
| Tastenkürzel | ⌘R mit Debugger starten, ⌃⌘R ohne, ⌘B bauen, ⌘U Tests, F9-Ersatz ⌘\\ für Haltepunkte, F10/F11/⇧F11 Schritte, F12/⇧F12, F2 | Mac-übliche Kürzel, Debug-Schritte wie gewohnt auf F-Tasten. |
| Inspektor | eigene rechte Spalte statt `.inspector` | `.inspector` verschiebt die rechten Toolbar-Knöpfe in seine (verborgene) Spalte. |
| Lokalisierung | Englische Texte als Schlüssel, `de.lproj/Localizable.strings`, von `build.sh` ins Paket kopiert | SwiftPM-Ressourcenbündel neben dem Executable brechen die Code-Signatur; Muster aus Seasons. |
| Bundle-ID | `io.github.lajumira.vslike` | Unverändert zur Avalonia-Version. |
| Klassendiagramm-Datei | Neue Diagramme sind `<Projekt>.cd` (XML wie in VS) im Ordner des Startprojekts bzw. des gewählten Ordners; neue Typen landen im Diagrammordner, bei einem Diagramm außerhalb aller Projekte im Startprojekt | Wunsch des Nutzers (2026-11-21): Diagramm und neue Klassen gehören neben Program.cs, mit Namespace des Projekts. `.cdiagram.json` wird nur noch gelesen. |
| Neue Projekte | `dotnet new … --use-program-main`; Vorlagen ohne diese Option (Exit-Code 127, nichts angelegt) ohne sie | Program.cs mit Namespace, Klasse `Program` und `Main` statt Top-Level-Anweisungen (Wunsch des Nutzers, 2026-11-21). |
| .NET SDK 10 oder neuer | Engine mit `RollForward=Major` (läuft auf .NET 10, sonst auf der nächsthöheren Laufzeit); Tests starten `dotnet` wie die App ohne geerbte MSBuild-Variablen; die Release-CI testet mit dem vorinstallierten SDK 11 statt es auszublenden | Wunsch des Nutzers (2026-11-21): Die App soll mit jedem SDK ab 10 laufen. Ein Mac mit nur SDK 11 hat keine .NET-10-Laufzeit. Der CI-Fehler MSB4216 unter SDK 11 kam aus den Test-Fixtures, die die vom MSBuildLocator gesetzten SDK-10-Variablen an `dotnet restore` vererbten. |
| Mitglieder im Diagramm | Nur der Name ist Pflicht; Standard `public` und `int` (auch Parameter), Methoden-Rückgabe `void`, Ereignisse `EventHandler` | Wunsch des Nutzers (2026-11-22), `void` für Methoden auf Rückfrage bestätigt. `int` ist für Ereignisse kein gültiger Typ, daher dort `EventHandler`. |
| Diagramm-Ansicht speichern | Zoom/Offset entprellt (500 ms), Pinch und ⌘-Scroll über lokalen NSEvent-Monitor statt `MagnifyGesture` | Jedes Trackpad-Ereignis schrieb die `.cd`-Datei und ließ alle Boxen neu berechnen; die SwiftUI-Geste lag nur auf der freien Fläche und griff über Boxen nicht (2026-11-22). |
| Ordner für neue Solutions | `UserDefaults` „projectsFolder“, Wahl im Dialog „Neue Solution“ wird gemerkt | Wunsch des Nutzers (2026-11-22). |
| Namespace neuer Dateien | Block-Namespace mit eingerücktem Inhalt; die Dateien von `dotnet new` werden nach dem Anlegen umgewandelt | Wunsch des Nutzers (2026-11-22, Vorlage: Program.cs mit `namespace test { class Program { … } }`); ersetzt die frühere Vorgabe file-scoped. Gilt auch für neue Typen aus dem Diagramm, damit alle erzeugten Dateien gleich aussehen. |
| StyleCop-Einstellungen | `stylecop.json` im Solution-Ordner, angelegt auf Befehl mit Firmenname/Copyright aus den globalen Einstellungen; beim Speichern lädt die Engine sie neu und parst alle Dokumente neu | StyleCop cacht seine Einstellungen pro Syntaxbaum; ohne Neuparsen gälte eine geänderte Datei erst nach dem Bearbeiten der jeweiligen Datei (2026-11-22). |
